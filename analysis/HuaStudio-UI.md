## 二、顶栏：三个视图模式

| 按钮 | 含义 |
|---|---|
| **Agent 剪辑** | AI 自动剪辑（本次未点开，待挖） |
| **美化** | 正常工作视图（本次全程在此） |
| **原始** | 原始素材视图（不含美化效果，用来对比） |

右侧 **导出** 是唯一的橙色主按钮——全界面只有它和滑块是橙色，视觉引导极清晰。

## 三、壁纸（背景）

文案：**壁纸会衬在画面背后，让录屏像发布会幻灯片一样有呼吸感。**

当前：**墨岩**（`slate`）

壁纸选择器（横排缩略图）：
- **清晰**（虚线框图标 = 不要壁纸，透明导出）
- **晨山**
- **雾湖**
- **云海**
- …（横向滚动）

命名全部是**中文意境词**，不是「背景 1/2/3」。包里 21 张 jpg 对应英文名：

~~~
aurora blush clouds dune dusk ember forest galaxy ink lagoon
lake midnight mist mountain porcelain sage sea slate washi wave
~~~

## 四、比例

文案：**画布形状。竖屏/方形会把画面摆进新画布、壁纸补满，预览和导出都按它构图。**

选项：**跟随源** / 16:9 / 9:16 / 3:4 / 4:5

「跟随源」是默认——不改变原始画幅。这是对质量敏感用户的正确默认，也解释了 `cfg.canvasAspect = "source"`。

## 五、画面（核心视觉参数）

### 留白 10%（本次调到 10%，默认 0.105 ≈ 10.5%）
> 画面四周留出的空间，越大越有悬浮感，留出来的地方露出壁纸。

### 圆角 20
> 画面边角的圆润程度，发布会风格一般在 12-24 之间。

**「发布会风格一般在 12-24 之间」** —— 这句话本身就是产品设计：给用户一个安全区间，降低决策成本。

### 阴影 0%
> 让画面从壁纸上浮起来，拉到 0 就是贴平。

默认 0 = 不做阴影。说明作者认为**最干净的观感是不加阴影**，而不是"加了更好看"。

### 裁剪画面…
二级面板，用于裁掉画面边缘（去掉菜单栏/无关区域）。

---

## 六、打码

> 遮住画面里不想露的地方：地址、邮箱、聊天记录瞬间。敏感信息一条不漏。

[加一块遮挡] 按钮。

对应类型骨架里的 `MaskRegion`（11 个字段）+ `MaskStyle { solid, pixelate }` + `Handle { tl,t,tr,r,br,b,bl,l }`（8 向拖拽手柄）。

也就是说：打码块可以拖动、缩放，样式支持纯色遮挡和像素化两种。

**四个平台预设**是 Screen Studio 完全没有的东西——一键把分辨率/比例/码率调成平台最优。这是中国市场的正确解法。

对应类型骨架：
~~~
ExportPreset      { 4 字段 }  → 平台预设
ExportResolution  { p4k, p2k, p1080, p720, original }
ExportFormat      { mp4, gif, prores }
ExportQuality     { high, standard, small }
ExportFPS         { 30, 60, source }
ExportAspect      { 16:9, 9:16, 3:4, 4:5, source }
~~~

| 界面元素 | 类型骨架里的名字 | 默认值 |
|---|---|---|
| 壁纸 | `cfg.background` | slate / 墨岩 |

| 阴影 | `cfg.shadow` | 0 |

## 十、文案风格（值得单独学）

这个产品的文案有统一范式：**不解释参数，只描述效果**。

| 参数 | 常见写法 | HuaStudio 写法 |
|---|---|---|
| padding | "内边距（像素）" | "画面四周留出的空间，越大越有悬浮感，留出来的地方露出壁纸。" |
| radius | "圆角半径" | "画面边角的圆润程度，发布会风格一般在 12-24 之间。" |
| shadow | "阴影强度" | "让画面从壁纸上浮起来，拉到 0 就是贴平。" |
| background | "背景图" | "壁纸会衬在画面背后，让录屏像发布会幻灯片一样有呼吸感。" |

**每句话都回答"我调这个会发生什么"，而不是"这是什么参数"。** 这是 8 MB 的小工具敢卖钱的底气。

## 十一、和 Screen Studio 的产品定位差异

| | Screen Studio | HuaStudio |
|---|---|---|
| 市场 | 全球（英文为主） | **中国（四平台预设）** |
| 体积 | 245 MB | 8.1 MB |
| 分发 | 官网 + 授权 | Mac App Store |
| 技术 | Electron | 原生 SwiftUI |
| 功能密度 | 极高（tRPC 150 个能力） | 高（够用，不堆） |
| 本地化 | 界面翻译 | **平台适配**（B站/小红书/抖音/视频号） |

**结论**：HuaStudio 不是 Screen Studio 的低配版，是**同一品类的中国解法**——用 1/30 的体积做到 80% 的能力，剩下的用平台预设补齐。

## 十二、"Agent 剪辑"到底是什么（已解）

它**不是内置 AI**。点开这个 tab，app 只做一件事：**生成一段提示词**。

~~~
用户点「Agent 剪辑」
   ↓
app 生成结构化提示词：
   · 这段录制的元信息（ID / 路径 / 时长 / 分辨率 / 有无摄像头麦克风）
   · 完整的 CLI 命令表（读/改/出 三类，含全部参数与取值范围）
   · 须知（beautify 开关、project.json 非破坏、运镜勿重叠、单段 1.5–4s）
   · "我的剪辑需求"填空位
   ↓
用户复制，粘给任意 AI（ChatGPT / Claude / Cursor / 本地模型都行）
   ↓
AI 通过 cli 子命令读写 project.json
   ↓
编辑器实时热重载，用户 ⌘Z 可撤回
~~~

### 这个设计的本质

**它没有做 AI 功能，它做了「让 AI 能用的接口」。**

一个 8 MB 的原生 app 不可能训模型、接不起 API 成本，但可以把**工具面**做到 AI 友好。于是它选择：

| 常规做法 | HuaStudio 做法 |
|---|---|
| 接 OpenAI API，内置对话 | 生成提示词，让用户自带 AI |
| 做 MCP server / 插件 | 一个 CLI，任何 agent 都能 exec |
| AI 直接操作 UI（点按） | AI 只读写一个 JSON |
| 用 RAG 检索文档 | 提示词里自带完整 API 文档 |

### 五个设计要点

**① 零集成集成**
不加依赖、不建服务、不做鉴权。一段文本 + 一个可执行文件 = 任何 AI 都能驱动它。连断网都能用（本地模型）。

**② 工具面 = 数据面**
所有命令最终只改 `project.json`。源视频永不改写。每次改动自动备份 `.bak`。**AI 再怎么乱来，素材是安全的。**

**③ 提示词即能力声明**
那段提示词本身就是完整 API 文档：命令、参数、取值范围、坑（"运镜段勿重叠"、"单段 1.5–4s 倍率 1.4–2.2"）。agent 读完就知道边界，不需要注册工具、不需要 RAG。

**④ 把 AI 幻觉挡在数据层外**
AI 只能改参数，碰不到渲染管线。渲染是 app 自己的事。所以 AI 出错最多是"剪得难看"，不会产出坏文件。

**⑤ 人在环，不是人出环**
编辑器开着也能剪，外部改动实时热重载，⌘Z 可撤回。这是**协作**，不是**托管**。

### 为什么这套东西值得抄

它解决了一个真实矛盾：**小团队想要 AI 能力，但养不起 AI 团队**。

HuaStudio 的答案是——**别做 AI，做 AI 的扳手**。你只需要保证：

1. 有一个可以脚本化的入口（CLI）
2. 有一个非破坏的数据层（project.json + 备份）
3. 有一份写给模型看的说明书（提示词模板）
4. 有一个能实时反馈的界面（热重载 + 撤回）

四件事加起来不到 100 KB 代码，但让这个 8 MB 的工具接上了全世界所有模型。

**Screen Studio 那 245 MB 里没有这个能力。** 它有能力，但没有接口。
